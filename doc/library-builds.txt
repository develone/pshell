pico-sdk what is the difference add_library(openjpeg INTERFACE) and add_library(openjpeg )

In the Raspberry Pi Pico SDK (which uses standard CMake), the difference lies in how the library 
is built and whether it contains its own source code.

Here is the direct breakdown of the two commands:

add_library(openjpeg INTERFACE)

This creates an Interface Library. It does not compile any source files of its own.

Purpose: Used as a "header-only" library or a collection of build configurations.

Source Files: Cannot have source files (.c, .cpp) directly attached to it.

Usage: It purely forwards header include paths, compiler flags, or other target dependencies to 
whatever links against it.

Pico Context: Often used to wrap external third-party code where you just want to point to an 
existing folder of headers and pre-compiled binaries.

add_library(openjpeg)

This creates a Standard Library (Static or Shared, defaulting to Static in the Pico SDK).

Purpose: Used to compile actual source code into a library binary (e.g., libopenjpeg.a).

Source Files: Requires you to provide source files right after the name, 
like add_library(openjpeg openjpeg.c jp2.c).

Usage: CMake will physically compile these files during the build process.

Pico Context: Used when you are writing or porting the actual C/C++ source code files for 
OpenJPEG to run on the RP2040/RP2350.

Summary Comparison

Feature						add_library(openjpeg 		add_library(openjpeg)
							INTERFACE)	
Compiles Code?				No							Yes
Requires Source Files?		No							Yes
Generates .a file?			No							Yes
